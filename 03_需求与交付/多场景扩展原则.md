# 多场景扩展原则

**项目：** 灵犀聊天数据中台（一期对外名：客服数据中台）  
**日期：** 2026 年 8 月 29 日  
**状态：** 已确认（一期只交付客服包；销售包、个人包不纳入本期验收）  
**确认：** 2026-08-29  
**关联：** `一期需求确认.md` · `一期技术方案.md`

> 产品线要能覆盖 **客服、销售、纯个人** 三种用法。一期把底座做对，场景差异全部放进「场景包」，不要为三种用法复制三套同步和会话库。

---

## 第一步：第一原理

| 问题 | 结论 |
|---|---|
| 三种场景真正共用什么 | 本机微信只读、联系人、会话、消息、去重、导出、本机存储 |
| 三种场景真正不同的是什么 | 谁在看、超时多长、雷达状态、主诉求词表、诊断问什么、界面叫什么 |
| 做错会怎样 | 按「客服系统」把角色、SLA、提示词写死，销售和个人只能 fork 仓库 |
| 一期做完三套会怎样 | 超出 ¥8,000 验收，庆总现场用不上销售包/个人包 |
| 结论 | **底座按通用聊天台设计；场景包可替换。一期只启用客服包。** |

与上一轮「个人客户能挖什么」的区别：

- **个人客户**：客服/销售场景里的**分析对象**（家长、老师、线索）。
- **纯个人**：产品的**使用场景**——自己的微信，给自己看待办和关系，没有主管、没有团队禁用词。

## 第二步：分层

```text
┌─────────────────────────────────────────┐
│ 场景包（可替换，一期仅 cs）                │
│  文案 · 雷达规则 · 默认超时 · 词表 · 提示词 │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│ 底座（三种场景共用，尽量不再分叉）          │
│  微信同步 · 联系人/会话/消息 · 去重 · 导出  │
│  本机库 · 模型配置 · 打开页面当场算规则     │
└─────────────────────────────────────────┘
```

消息角色在库里今天写成 `cs` / `customer` / `system`。语义上应对齐采集层已有的本机标记（`我` / `me`）：

| 库字段（现状） | 稳定语义 | 客服包叫法 | 销售包叫法 | 个人包叫法 |
|---|---|---|---|---|
| `cs` | 本机登录号发出 | 客服 | 销售 / 我 | 我 |
| `customer` | 对端发出 | 客户 | 线索 / 客户 | 对方 |
| `system` | 系统 | 系统 | 系统 | 系统 |

一期**不改字段名**（避免无收益迁移）。新规则和新文案按「本机 / 对端」理解，不要再假设世界上只有客服。

## 第三步：三个场景包（口径草案）

### 客服包 `cs`（一期交付）

- 使用者：管理人员复盘客服。
- 雷达：待回复、新询盘、跟进中、沉寂；风险 / 超时 / 承诺未兑 / 禁用词。
- 超时：秒级 SLA（默认 180 秒）。
- 诊断：响应、口径、规则告知、亲和力；对象是客服表现。
- 不做：自动回复、人物画像。

### 销售包 `sales`（后续）

- 使用者：销售本人或主管看线索。
- 雷达侧重漏斗代理：新询盘、已发未回、决策卡点、承诺未兑、沉寂。
- 超时：跟进时效（小时级更合理，不是 180 秒客服 SLA）。
- 主诉求：价格、档期、竞品、成交阻碍；退费/投诉降权或另表。
- 诊断：促单、跟进密度、报价口径是否一致；对象是销售动作。
- 仍共用：同步、会话、点进原聊天。

### 个人包 `personal`（后续）

- 使用者：自己看自己的微信。
- 雷达：我欠回复、对方沉寂、我承诺过、长期未联系；弱化「客户」「禁用词」「客服诊断」。
- 超时：按「我自己能接受的等待」配（小时～天），不是团队考核。
- 诊断可改成关系备忘 / 待办摘要，或默认关掉模型分析。
- 更强调剔除公众号、服务通知；没有团队排名、没有多设备上报的必要性。

三种包都**只读、不发送**。扩展场景不等于帮聊托管。

## 第四步：一期要预留、不要提前做

| 现在就守住 | 现在不要做 |
|---|---|
| 同步与消息表不按场景分叉 | 三个前端仓库、三套表 |
| 雷达 / 词表 / 提示词 / 文案可整包替换 | 设置页上线「切换场景」（庆总一期用不上） |
| 新规则用本机/对端，不写死「只有客服才超时」 | 把 `cs`/`customer` 全库改名 |
| 文档写明产品线三包，验收仍只考客服包 | 销售漏斗、个人关系页纳入本期验收 |

落地时一个场景包建议包含：`id`、界面名词、默认 `timeout_seconds`、雷达状态与诉求规则、词表种子、分析提示词路径、导航里显示哪些页（个人包可隐藏效率考核）。

**怎么做成积木、不做界面切换：** 见 [场景包积木式落地.md](./场景包积木式落地.md)。不是三套独立应用；启动时用 `LINGXI_SCENARIO` 绑死一个包。一期不拆目录。
