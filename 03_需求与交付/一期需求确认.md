## 1. 一期目标与成功标准

一期要在庆总指定环境中跑通这条闭环：

```text
读取客服聊天数据 → 结构化整理与筛选导出
        → 规则统计 + 客户自备模型 AI 分析
        → 基础前端查看结果
        → 真实客服数据验证
```

**一期成功标准（业务口径）：**

1. 能把本机登录客服号的聊天记录同步进来，整理成可查询、可导出的结构化数据；
2. 能按客服、时间看到响应效率和基础诊断结论；
3. 管理人员打开客户雷达能看到「明天先跟谁、他在问什么、有没有风险」，并点进对应会话；
4. 管理人员能在基础页面里完成一次真实复盘；
5. 在指定环境完成一次部署与真实验证，交付源码和说明文档。

一期以「清晰可用、能支持真实复盘」为标准，不以复杂大屏、完整商业化后台或二期集中上报为交付目标。

产品线后续可换场景包覆盖销售、纯个人（共用同步与消息模型，替换雷达/超时/词表/提示词/文案）。**本期交付与验收仅客服包**，见 [多场景扩展原则.md](./多场景扩展原则.md)。「纯个人」指自己用自己的微信，不是客服雷达里的个人客户对象。

## 2. 角色与使用场景

| 角色 | 典型动作 | 本期是否覆盖 |
|---|---|---|
| 管理人员 / 复盘人员 | 同步本机微信、看客户雷达跟进名单、按客服和时间筛选、看效率与诊断、导出明细 | 覆盖 |
| 客服人员 | 不在本期作为独立用户角色；其聊天数据作为分析对象 | 不单独做客服端 |
| 系统管理员 | 配置模型 API、超时阈值、禁用词，查看同步/分析任务状态 | 覆盖（基础配置） |

**主场景 SC-01：真实复盘**  
管理人员选定时间范围，先在客户雷达看待回复/风险/沉寂名单并点进会话；再查看首次/平均响应、超时未回、禁用词、高频问题、未解决会话，并导出该范围聊天明细。

**主场景 SC-02：本机同步**  
在指定电脑上触发微信同步，系统完成结构化、去重和任务状态展示；数据量较大时后台处理，页面可查看进度和失败原因。

**主场景 SC-03：诊断迭代**  
根据庆总提供的话术规则和分析关注点，调整禁用词、超时阈值后重新统计；对选定范围触发一次 AI 分析并查看建议。

## 3. 功能需求

优先级：P0 必须交付；P1 本期应交付，实现深度可按样例数据收敛；P2 有则更好，不阻塞验收。

### 3.1 数据读取与本地整理

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-01 | 支持多个客户会话入库 | P0 | 一期单机读取「当前登录客服微信号」下的多个客户会话；不按客户数收费。多客服微信号、多台电脑归二期 |
| FR-02 | 消息基础字段结构化 | P0 | 至少包含：客服账号、客户/会话标识、消息时间、发送方（客服/客户/系统）、消息内容、消息类型 |
| FR-03 | 会话切分 | P0 | 将连续聊天归入会话，便于统计响应和做会话级诊断 |
| FR-04 | 按客服账号、时间范围筛选 | P0 | 筛选结果用于查看、分析和导出 |
| FR-05 | 按筛选范围导出 | P0 | 导出 Excel 或 CSV，字段与结构化结果一致（导出结果，不是从文件导入） |
| FR-06 | 数据保存在客户指定环境 | P0 | 默认本机存储；我方不作为长期数据保管方 |
| FR-08 | 本机微信只读同步 | P0 | 读取本机已登录微信的聊天记录（实现上对齐灵犀 wechat-cli，**对用户隐藏该组件名**）。只读、不发送、不改微信原数据。Windows 基线微信 PC 4.1.9.0。**本期唯一数据来源** |
| FR-09 | 同步去重 | P0 | 同一条消息重复同步不产生多条有效记录 |
| FR-10 | 非文本消息可识别 | P1 | 图片、语音、文件等记为 `[图片]` `[语音]` 等占位；一期不做语音转写、截图识别 |

**数据读取边界：**

- 聊天数据**只从本机已登录微信同步**，不做 xlsx/csv/json/txt 文件导入。
- 本期是被动读取、整理、分析。不包含 AI 自动回复、主动发送、智能托管；**不接入灵犀帮聊的发送与监听进程**。
- 读取组件本身无发送能力；中台也不得通过 UI 自动化发消息。
- 界面、报错、使用说明对客户**不出现 wechat-cli** 等第三方工具名；只说「微信同步 / 微信读取初始化」。
- 「不限制客服号」指系统能力不按账号授权收费；单机一次对应当前登录的一个微信号。超出约定电脑数量的部署、复杂环境排查、大规模历史迁移需另行确认。

### 3.2 规则统计（不依赖模型）

以下指标在本地计算，模型 API 不可用时仍应能查看。

| 编号 | 需求 | 优先级 | 计算口径（默认，可配置） |
|---|---|---|---|
| FR-11 | 客服首次响应时长 | P0 | 一个会话内，客户首条有效消息到客服第一条回复的时间差 |
| FR-12 | 平均响应时长 | P0 | 客户每条待回复消息到下一条客服回复的时间差，按客服/时间范围求平均 |
| FR-13 | 超时未回复统计 | P0 | 超过超时阈值仍无客服回复的客户消息数/会话数；默认阈值 180 秒，可配置 |
| FR-14 | 按客服、按日汇总效率 | P0 | 消息数、会话数、首次响应、平均响应、超时次数 |

会话切分默认规则：同一客服与同一客户之间，消息间隔超过 12 小时视为新会话。若本机数据自带会话标识，优先使用原标识。

### 3.3 话术与风险检测

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-15 | 禁用词/风险表达检测 | P0 | 按可配置词表扫描客服发出的文本；命中后记录消息、会话、客服、时间 |
| FR-16 | 基础话术标记 | P1 | 对客服常用开场、结束、转接等话术做命中统计；词表由客户提供，未提供则先给可编辑默认表 |
| FR-17 | 词表配置 | P0 | 管理人员可维护禁用词、关注话术；修改后对选定范围重新扫描，不必重导数据 |

### 3.4 AI 分析（使用客户自备模型）

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-18 | 客户高频咨询问题归纳 | P0 | 按选定客服/时间范围归纳高频问题及大致占比或频次 |
| FR-19 | 未解决问题识别 | P0 | 标出客户问题未被有效回答、或明显未闭环的会话 |
| FR-20 | 重复追问识别 | P0 | 标出客户反复追问同一问题的会话 |
| FR-21 | 需要关注的会话总结 | P0 | 给出简短摘要和关注原因 |
| FR-22 | 按客服/时间给出优化建议 | P0 | 结合效率指标与会话结论，输出可执行的改进建议 |
| FR-23 | 分析任务可追踪 | P0 | 可查看分析任务状态、范围、失败原因；支持对同一范围重跑 |
| FR-24 | 分析结果可回溯 | P1 | 页面展示所依据的时间范围、客服范围和任务时间，避免「不知道这是哪批数据」 |

AI 分析只在用户触发或约定批量任务时调用模型，不在每次打开页面时静默全量重跑。

## 4. 明确不包含（一期）

与商务方案保持一致，下列内容本期不做，后续按实际需求评估：

- 聊天记录文件导入（xlsx / csv / json / txt 等）；
- AI 自动回复、自动发送消息、营销触达、智能托管；
- 灵犀帮聊的截图视觉补全（语音转写、图片理解）；
- 完整多角色权限、审批流、复杂实时看板、可视化大屏；
- 人物画像、六维评分、复杂自定义评分规则、客服横向排名（**客户雷达不是画像**：只做联系人经营名单与规则标记，见 FR-38）；
- 企业微信、CRM、ERP 或其他第三方系统对接；
- 多电脑大规模部署、历史数据大规模迁移；
- 语音转写、图片 OCR、多模态分析；
- 销售场景包、纯个人场景包（含场景切换、销售漏斗页、个人关系页）；本期不验收；
- 二期的设备上报与统一汇总后台；
- 长期驻场或无限次迭代维护。

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 部署形态 | 以客户指定电脑本地部署为主；可单机启动，不强制依赖云服务器 |
| NFR-02 | 数据主权 | 聊天数据、分析结果、API Key 均留在客户环境；我方不代管 Key、不长期留存业务数据 |
| NFR-03 | 出站范围 | 业务运行期默认仅访问客户配置的模型 API；不把聊天数据发到我方服务器 |
| NFR-04 | 只读约束 | 只读本机微信库，不发送消息，不修改微信原数据，密钥不带离客户机 |
| NFR-05 | 可维护 | 配置与词表可改；源码结构清晰，便于客户内部二次开发 |
| NFR-06 | 失败可见 | 同步失败、模型调用失败、部分会话分析失败时，页面能看到**中文业务原因**，不静默丢数据，也不把第三方命令名抛给用户 |
| NFR-07 | 体量假设 | 一期按单机、约定账号、近期数据设计。单次分析建议先按「最近 N 天 / 选定账号」运行。超大规模历史库需另行评估 |
| NFR-08 | 操作系统与微信 | 对齐灵犀：Windows 10/11 + 微信 PC 4.1.9.0；若为 Mac，微信 4.1+ 需走同款密钥适配。版本以测试机确认 |
| NFR-09 | 隐藏读取组件 | 实现必须内嵌并隐藏 wechat-cli：无控制台黑窗、不进系统 PATH、客户文档/界面/快捷方式不出现该名称 |
| NFR-10 | 场景可替换 | 采集与消息表不按场景分叉。雷达、词表、提示词、界面名词、默认超时随场景包替换。一期只启用客服包，不要求设置页切换场景 |

性能不承诺高并发。单机页面查询和导出以「管理人员使用」为准，秒级到可等待的分钟级均可接受；全量 AI 分析允许异步任务。

## 8. 验收标准

对应商务方案 P1 / P2 / P3。下列全部满足即可一期验收。

### 8.1 P1 数据链路

- 在已完成「微信读取初始化」的环境，能列出本机会话并拉取历史，结构化落库（客服=本机登录号，客户=对端）；
- 页面或导出中能看到客服、时间、发送方、内容等基础字段；
- 能按账号和时间范围筛选，并导出该范围数据。

> 微信读取初始化失败（版本/权限）时，P1 视为环境未就绪，不改走文件导入。客户侧验收用语为「微信同步」，不出现第三方工具名。

### 8.2 P2 分析与前端

- 选定范围内能看到首次响应、平均响应、超时未回；
- 首页客户雷达能按联系人列出待回复 / 新询盘 / 跟进中 / 沉寂，展示主诉求与风险/超时/承诺未兑/禁用词标记，点行进入会话；规则不调用模型；
- 禁用词可配置，命中结果可查；同步成功或效率页「重新统计」后，雷达上的禁用词标记可更新；
- 配置客户模型后，能对选定范围跑出：高频问题、未解决/重复追问、会话关注摘要、优化建议；
- 基础前端可演示上述结果，并能查看同步/分析任务状态。

### 8.3 P3 真实验证与交付

- 在指定环境用真实数据完成一次端到端验证；
- 验收范围内问题已修复或双方书面确认挂起；
- 交付一期源码、配置模板、部署说明、使用说明；
- 无机器码、无账号授权限制。
