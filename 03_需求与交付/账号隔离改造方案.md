# Judy · 微信号数据归属改造方案

**依据：** 一期技术方案 §4～§5；二期「多设备上报与后台汇总」方案  
**日期：** 2026 年 9 月 1 日  
**范围：** 先改本机库的数据归属，为后续管理员查看全部微信号留口；**本次不实现中心后台、上报、登录角色。**

---

## 1. 结论与目标

一期库表已经给聊天事实挂了 `account_id`，但运行时把所有数据写进唯一一行 `account_key="local"`。授权用的 wxid 只决定「这台 Judy 能不能开」，不决定「能看见哪几行」。

改造后要达到：

1. **一个微信号一行 `accounts`**，`account_key` 与授权用的文件夹 wxid 同一套规范化规则。
2. **本机客服默认只看当前登录号** 的会话、消息、群、诊断、统计。
3. **同一 `data-dir` 里可以并存多个号**（换过微信目录、或以后管理员库汇总），互不覆盖、不去重误伤。
4. **授权名单 ≠ 数据可见范围。** 许可证里的多个 wxid 只表示许可使用；查数仍走账号归属，以后再加组织 / 角色。

不在本次做：多用户登录、管理员 Web、设备上报、按组织拆库、提示词/词库按号隔离。

---

## 2. 目标模型（三层，先做两层）

```text
[组织 org]          二期中心后台才需要；本机 Judy 隐含「这一台安装 = 一家客户」
    │
    ▼
[微信号 accounts]   本次必须落地：account_key = 规范化 wxid
    │
    ▼
[聊天事实]          已有 FK，改为真正写入当前号
    contacts / conversations / messages
    metric_daily / hit_records / analysis_jobs
```

身份字段约定：

| 字段 | 含义 | 来源 |
|---|---|---|
| `accounts.account_key` | 稳定隔离键，库内唯一 | `folder_wxid()`：`wxid_` 目录去掉设备后缀，否则用完整目录名（与授权一致） |
| `accounts.wx_username` | 系统会话 wxid，供展示/对照 | 解密库推断；可空 |
| `accounts.display_name` | 客服昵称 | 手填优先，不随同步覆盖 |

`peer_key` 仍是对端（好友/群）标识。同一家长加了两个客服号，在两个 `account_id` 下各有一行联系人，这是正确切分，不是重复数据。

## 3. 现状缺口（相对目标）

| 点 | 现状 | 风险 |
|---|---|---|
| 写入账号 | `_local_account()` 固定 `"local"` | 换号仍写入同一桶，聊天混在一起 |
| 查询默认范围 | `account_id` 可选，不传=整库 | 前端从不传；多号后会串号 |
| 群列表 / 部分统计 | `list_groups` 等未接 `account_id` | 群画像会看到别的号的群 |
| 分析任务 | `account_id` 可空，历史列表不按号过滤 | 诊断报告/群报可能跨号 |
| 同步任务 | `sync_jobs` 无 `account_id` | 无法判断哪次同步属于哪个号 |
| 消息去重 | `raw_hash` 不含账号，全局 `UNIQUE(raw_hash)` | 两号对同一人同一分钟同一句，后写入被丢 |
| 提示词 / 词库 / 设置 | 无账号字段 | 本机共享可接受；中心多租户时再拆 |
| 授权 | 许可证绑定文件夹 wxid | 与行级可见范围无关，不要混用 |

一期方案写过：`raw_hash` = 账号 + 对端 + 时间 + 角色 + 正文。实现对端已做，账号未做，本次一并补上。

---

## 4. 本机行为（改造后）

启动 / 同步 / 读页时解析 **当前文件夹 wxid**。

- 能解析到：`get_or_create` 该 `account_key` 的 `Account`，同步只写入这一行；页面默认只读这一行。
- 解析不到（微信目录未就绪）：**禁止同步**；只读上次成功识别的号（若库里有），否则空状态。不再新建 `"local"`。
- 同一 `data-dir` 里已有其它号：数据保留。默认仍看当前号；设置里可列出本机出现过的号（只读切换，给排查用）。客服日常不需要手动选号。
- 许可证未包含当前 wxid：保持现有「未授权」闸门，**不删除**库里其它号的数据。

清空数据（`POST /data/reset`）：仍清空会话/消息/分析，**保留 `accounts` 行**（避免昵称和 wxid 对照丢失）。若产品要坚持「全盘清空」，需在接口说明里写清，并单独确认。

## 5. 迁移（已有 `lingxi.db`）

现场多半已经是一行 `"local"` + 一批聊天。升级时自动做，不要求客户重同步。

1. 读当前 `folder_wxid()`。
2. 若库中仅有 `account_key="local"`：
   - 当前 wxid 非空 → 把该行 `account_key` 改成当前 wxid，并回填 `wx_username`（若空）。
   - 当前 wxid 为空 → 暂时保留 `"local"`，**第一次成功识别到 wxid 时再改名**；此期间同步仍只允许在识别成功后写入。
3. 若已存在目标 wxid 行，同时又有 `"local"`：把 `local` 下 `contacts / conversations / messages / metric_daily / hit_records / analysis_jobs` 的 `account_id` 改到目标行（按 `peer_key` 合并联系人：目标已有则把会话/消息改挂到已有 contact），然后删除空的 `"local"` 行。冲突时目标行优先。
4. `messages.raw_hash` 历史值不重算（重算要扫全文且无法与旧哈希对齐）。改为唯一约束 **`(account_id, raw_hash)`**；新写入的哈希带上 `account_key`。旧行继续用旧哈希，只在本账号内去重。
5. `analysis_jobs.account_id` 为空的：能从关联结果对应消息推断则回填，否则填迁移后的当前账号。
6. 迁移写一条 `app_settings` 键，例如 `account_key_migrated=1`，保证只跑一次。

用现有客户库做一次备份后的演练（拷贝 `lingxi.db` 跑迁移断言），再发版。

## 6. 接口与查询契约

新增一个解析函数（名称示例：`resolve_account_scope`），所有列表/统计/分析入口统一走它，禁止各接口自己 `if account_id: filter`。

| 调用方 | `account_id` 参数 | 实际范围 |
|---|---|---|
| 本机客服页（默认） | 不传 | **当前 wxid 对应账号**（不是整库） |
| 本机设置「查看历史号」 | 传入该号 id | 仅该号；且必须是本库已有行 |
| 以后管理员 | 不传或 `all` | 组织内全部号；**本机接口先不开放 all** |

必须接上范围的入口（现在漏的一起补）：

- 会话列表、消息列表、会话详情
- 群列表、群成员、群报历史
- 诊断报告 / 分析任务与历史（`kind=report|scene` 也按当前号）
- 日统计、词表扫描、客户雷达
- 同步：任务行带 `account_id`；写入 contact/conversation/message 用当前账号

`GET /accounts` 增加：`wx_username`、`is_current`、消息/会话条数（可选）。  
`GET /wechat/status` 增加：`account_id`、`account_key`（当前号）。

安全口径：本机无登录角色时，**不允许**用参数看到「全部账号混合列表」。切换历史号只能点选本机已存在的 `accounts` 行。管理员 `all` 留给二期中心服务，用角色闸门，不要在本机 Judy 上先开一个无鉴权的全库接口。

## 7. 表结构改动

| 表 | 改动 |
|---|---|
| `accounts` | 语义改为 wxid；禁止再插入 `"local"`（迁移完成后） |
| `sync_jobs` | 新增 `account_id`（可空兼容旧行，新任务必填） |
| `messages` | 去掉全局 `UNIQUE(raw_hash)`，改为 `UNIQUE(account_id, raw_hash)` |
| `analysis_jobs` | 新任务 `account_id` 必填；列表过滤当前号 |
| `prompt_templates` / `lexicon` / `app_settings` | 本期不拆，整机共享 |

`raw_hash` 新算法：

```text
sha256(account_key + "|" + peer_key + "|" + msg_time.isoformat() + "|" + role + "|" + sender + "|" + content)
```

---

## 8. 前端

本机仍是「当前微信」工作台，不做成账号管理后台。

- 顶栏或微信同步页展示当前 `account_key`（已有 wxid 展示则对齐同一来源）。
- 会话 / 群 / 诊断请求带当前 `account_id`（或完全依赖后端默认当前号，前端不必自己猜）。
- 仅当 `GET /accounts` 返回多于 1 条时，设置页出现「本机出现过的微信号」只读列表，可切换查看，并明确「不影响当前同步写入哪个号」。
- 不在诊断报告、群画像里做跨号汇总。跨号汇总是二期管理员页的事。

## 9. 实施顺序

### A1 归属与迁移（本机可发版）

- `get_or_create_account(wxid)` 替换所有 `_local_account` / `_local_account_row`
- 启动或打开库时跑 §5 迁移
- 同步写入当前号；`raw_hash` 与唯一约束
- `sync_jobs.account_id`
- 单测：两号同 peer 不同 `account_id`；迁移 `"local"` → wxid；哈希碰撞不再跨号

### A2 查询默认当前号

- `resolve_account_scope` 接到 §6 全部入口（含 `list_groups`、分析历史）
- 分析任务创建时写入当前 `account_id`
- 前端接当前账号；多号时设置页只读切换
- 回归：会话、群、诊断、统计只出现当前号数据

### A3 本机多号验收

- 同一 `data-dir` 先后同步两个微信目录（或测试夹具插入第二号）
- 断言：联系人/消息不混；切换查看互不污染；当前号同步不改另一号
- 授权失败不影响已有其它号数据

### B 二期中心后台（另立项，对齐现有二期方案）

不在本次开发。依赖 A 完成后再做：

- 组织 / 设备令牌 / 上报增量消息（必须带 `account_key`）
- 管理员角色：按组织看全部号，按客服/时间筛选、导出
- 提示词、词库是否按组织共享再定
- 本机 Judy 继续只写本号；管理员不跑在客服电脑的无鉴权接口上

## 10. 验收

A 阶段（本机改造）通过即可发版：

1. 新库同步后 `accounts.account_key` 等于当前文件夹 wxid，且只有这一号的聊天。
2. 旧库升级后 `"local"` 消失或改名为当前 wxid，历史会话仍在，条数不丢。
3. 测试库插入第二号后，默认列表、群、诊断均不含该号；切换后只看到该号。
4. 两号对同一 `peer_key` 写入相同正文，两条消息都在，各挂各的 `account_id`。
5. 许可证绑定与数据行数无关：未授权时不能同步，已入库数据仍在。

B 阶段沿用《灵犀·客服数据中台_二期数据汇总后台方案》的六条验收，不在此重复。

---

## 11. 风险与不做什么

- **微信目录名不是 `wxid_`：** 继续用完整目录名当 `account_key`（与现网授权一致，例如 `nxss11_c6ad`）。
- **先开 Judy 后才有微信目录：** 识别成功前不同步、不造 `"local"`。
- **媒体文件：** 仍按本机 `data-dir/media` 存放，路径不按号分子目录（A 阶段足够；B 阶段中心存储再拆）。
- **不做：** 本机管理员看全号混合报表、跨号 AI 分析、按号复制提示词、云端多租户鉴权。

---

## 12. 已确认决策

1. 本机设置在出现过多个微信号时，提供「查看历史微信号」只读切换；默认仍为当前登录号，同步始终写入当前号。
2. `POST /data/reset` 保留 `accounts` 行，只清聊天、统计与分析结果。
3. A1+A2 随下一版 Judy 一起发；A3 用测试夹具验收，不必等客户双号现场。
