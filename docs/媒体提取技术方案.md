# 媒体提取技术方案

实施内部文档，不对客户展示。归档日期 2026-08-29。

覆盖一期已落地能力：微信同步时提取**已查看图片**、**语音原条（转 MP3）**、**已下载附件**，在会话明细预览或下载。数据只在客户本机，不上传。

---

## 1. 结论与边界

| 类型 | 能提取 | 不能提取 | 落盘形态 |
| --- | --- | --- | --- |
| 图片 | 用户已在微信里点开过原图，本机 `temp` 留下可预览 PNG/JPG | 未点开原图；仅有加密 `_t.dat` 缩略图；用数据库密钥或消息 XML 里的 aeskey 都解不开本机 dat | `data/media/image/` |
| 语音 | 消息库能对上的语音原条（SILK） | 对不上会话或库里没有 `voice_data` 的 | `data/media/voice/*.mp3`（转码失败则保留 `.silk`） |
| 附件 | 用户已在微信里下载到本机的文件 | 只看到文件名、尚未本地下载的 | `data/media/file/` 原格式 |

三句话：

1. **图片看的是明文缓存，不是解开 dat。** 点开原图后 `temp` 里有一份与 XML `length` 等长的 PNG/JPG；未点开时 attach 里通常只有 V2 加密 `_t.dat`。
2. **语音用的是数据库密钥。** 与「微信读取初始化」写入的 SQLCipher 钥匙是同一套，用来解密 `message/media_0.db` / `media_1.db`，取出 `VoiceInfo.voice_data`。
3. **附件是磁盘上的成品文件。** 路径在 `msg/file/YYYY-MM/`，魔数即 PDF/Word/zip 等，不需要再解密。

明确否决：

- 不扫微信进程内存取「设备级图片 AES 密钥」（那是解 `_h.dat` / `_t.dat` 的另一把锁，与数据库密钥不是同一把）。
- 不自动点开原图、不自动下载文件。
- 不把读取组件名称、密钥、wxid、聊天原文写进对客户日志或界面。

---

## 2. 总流程

同步每个联系人时：拉历史文本 → 解析消息类型 → 按时间对齐本机媒体元数据 → 拷贝/转码到 `data/media/` → 写入 `messages` 的媒体四列。

```
微信同步
  → parse_history_lines（[图片]/[语音]/[文件]）
  → attach_media(parsed, peer_key)
       → load_native_media：读取组件解密缓存 Msg_{md5(wxid)}
       → 图片 / 语音 / 文件 各走专线
       → save_bytes：按内容 sha256 去重
  → 插入或补写 messages.media_*
会话明细
  → GET /api/conversations/{id}/messages（has_media / media_mime / media_status）
  → GET /api/messages/{id}/media（只允许 data/media 内相对路径）
```

代码入口：

| 步骤 | 位置 |
| --- | --- |
| 同步中调用 | `backend/app/ingest/wechat_cli/sync_job.py` |
| 解析占位符 | `backend/app/ingest/wechat_cli/parse.py` |
| 提取与落盘 | `backend/app/ingest/media/extract.py` |
| 消息元数据 / 语音 blob | `backend/app/ingest/media/msg_index.py` |
| SQLCipher 页解密 | `backend/app/ingest/media/sqlcipher.py` |
| SILK → MP3 | `backend/app/ingest/media/silk_mp3.py` |
| 去重存储与防穿越 | `backend/app/ingest/media/store.py` |
| 账号根目录 / 库密钥 | `backend/app/ingest/media/wx_paths.py` |
| 媒体接口 | `backend/app/routers/api.py` |
| 明细预览 | `frontend/src/views/Conversations.vue` |

账号根目录：读取组件 `config.json` 的 `db_dir`（`db_storage`）的上一级，即 `xwechat_files/<账号>/`。

消息与媒体时间对齐（`take_native`）：

- 历史时间只有到分钟（秒为 0）：对齐该分钟内未使用的同类消息。
- 否则先 ±2 秒，再放宽到 ±90 秒。
- 命中后标记 `used`，避免两条语音抢同一条 blob。

`media_status`：`ready` 已落盘；`missing` 本机没有可预览原件。清空数据时同时清空 `data/media/`。

## 3. 图片

### 3.1 本机真实形态（Mac 实测）

点开原图之后：

- attach：`msg/attach/<md5(wxid)>/YYYY-MM/Img/` 下有 `_h.dat`（V2 头 `07 08 V2`，体积 ≈ 明文 + 31 字节）。
- **可预览明文**在 `temp/`（常见 `temp/InputTemp/`）：PNG/JPG，字节数等于消息 XML 的 `hdlength` / `length`，也等于 `_h.dat` 体积减 31。

未点开原图：

- 通常只有 `_t.dat` 缩略图，同样是 V2 加密。
- `temp` 里对不上等长明文。

不要用读取组件 `history --media` 取图：它会在月份目录里取第一个非 `_h` 文件，多条图会指到同一张缩略图，并故意跳过高清档。

### 3.2 现行提取步骤

```
历史行 [图片]
  → 消息缓存 type=3，解析 XML：md5、length/hdlength、aeskey
  → 在该会话当月 Img/ 找非缩略 dat（优先文件名含 md5 的 _h.dat）
  → 候选体积：XML length，以及 dat 体积 − 31
  → 在账号根 temp/ 下按「体积完全相等 + 魔数为 JPEG/PNG/GIF」找明文
     多份时取 mtime 最接近消息时间的一份
  → 拷贝到 data/media/image/
```

`temp` 按体积建一次索引，同步一个联系人只扫一遍，避免每张图 rglob。

实现里仍保留对 `_h.dat` 用 XML `aeskey` 解密的兜底（`dat_decrypt.py`）。**本机复核：该 aeskey 打不开 V2 dat**，所以一期实际生效的只有 temp 明文路径。

### 3.3 密钥边界（已实测）

| 钥匙 | 用途 | 能否打开 `_h.dat` / `_t.dat` |
| --- | --- | --- |
| 读取初始化写入的 SQLCipher `enc_key`（含派生 16 字节） | 解密 `db_storage` 里的库 | 否 |
| 消息 XML `aeskey` / `cdnthumbaeskey` | CDN 传输侧 | 否 |
| 微信内置 V1 固定密钥 | 旧版 XOR/V1 dat | 本机 V2 样本否 |
| 微信进程内设备级图片 AES 密钥 | 解开本地 V2 dat | 能，但一期不采集 |

因此：**未点开原图时，缩略图文件在磁盘上，但不能变成可预览图。** 会话明细显示「本地没有已缓存的原文件」。若将来要解 dat，必须另做进程内存取图密钥，与现有数据库密钥无关。

### 3.4 界面

`media_mime` 以 `image/` 开头则 `<img>` 预览，点击走 `/api/messages/{id}/media`（inline）。

## 4. 语音

### 4.1 本机真实形态

- 读取组件 `history --media` 去的是 `msg/attach/.../Voice/`，本机可以没有这个目录，开关无效。
- 原条在 SQLCipher 库 `db_storage/message/media_0.db` 与 `media_1.db` 的 `VoiceInfo.voice_data`。
- 头为 `\x02#!SILK_V3`（微信多一个 `0x02` 前缀）。
- 同一联系人可能只在 `media_1` 不在 `media_0`，必须两个库都解。
- 浏览器不能直接播 SILK，一期转 MP3 后播放。

### 4.2 提取步骤

```
历史行 [语音]
  → 消息缓存 type=34，XML voicemsg.length（SILK 字节数）
  → 用读取组件密钥解密 media_0 / media_1（按源库 mtime+wal 做缓存，写入 data/cache/）
  → Name2Id.user_name = wxid 得到 chat_name_id
  → 优先：length(voice_data)=xml length 且 create_time ±90 秒
  → 否则：仅时间窗口 ±90 秒
  → 去掉 0x02 后 silk-python 解成 s16le PCM（优先 24000 Hz，失败再 16000 / 12000）
  → ffmpeg libmp3lame → voice.mp3
```

依赖：`silk-python`、本机 `ffmpeg`（`PATH` 或 `/opt/homebrew/bin/ffmpeg`）。转码失败则落盘原始 SILK，明细里改为下载而不是播放。

首次解密两个语音库会有数秒到十几秒，同步日志只写「提取本机已缓存的图片、语音和文件」，不写密钥路径。

### 4.3 界面

`audio/mpeg` 用 `<audio controls>`；仍为 `audio/silk` 时提供下载。

## 5. 附件

### 5.1 本机真实形态

已下载文件在 `msg/file/YYYY-MM/`，就是 PDF / Word / zip 等成品，魔数真实。

未下载：历史里只有 `[文件] 文件名`，该月目录没有对应文件。

### 5.2 提取步骤

```
历史行 [文件] 文件名
  → 消息缓存 type=49 且 appmsg.type=6，取 title
  → 先在消息时间所在月目录精确匹配文件名
  → 再扫其它月份目录；允许文件名互相包含（微信有时加前缀）
  → 按魔数识别 mime，拷贝到 data/media/file/
```

不走 `history --media`。有真实路径时同步日志仍只报数量，不报文件名原文以外已在消息正文里的标题。

### 5.3 界面

非图片、非可播音频：链接下载/打开，`Content-Disposition: attachment`。

## 6. 存储与接口约定

落盘：`data/media/{image|voice|file}/{stem}_{sha256前16}.{ext}`，相同内容不重复写。

表 `messages` 四列：`media_relpath`、`media_name`、`media_mime`、`media_status`。已存在消息若缺媒体或仍是 SILK 而新结果是 MP3，同步时补写。

`GET /api/messages/{id}/media`：`resolve_media_path` 拒绝 `..` 与目录外路径；图片与 MP3 inline，其余 attachment。

`data/media/`、`data/cache/` 已 gitignore。不要提交密钥、`.env`、聊天原文、媒体原件。

## 7. 本机复核摘要（2026-08）

| 项 | 结果 |
| --- | --- |
| 已点开原图 | temp 明文体积 = XML length = `_h.dat` − 31，可预览 |
| 未点开原图 | 仅 `_t.dat`，数据库密钥与 XML aeskey 均无法解密 |
| 语音 | `media_0`/`media_1` 可解出 SILK；对时后转 MP3 可播 |
| 已下载附件 | `msg/file/YYYY-MM/` 原件可拷；未下载的只有文件名 |
| `history --media` | 文件有时可用；图片会指错文件，不用 |

后续若要扩大边界，只允许新增「设备级图片密钥」或「用户手动点开/下载后再同步」，不要把 SQLCipher 钥匙误当成图片钥匙。
